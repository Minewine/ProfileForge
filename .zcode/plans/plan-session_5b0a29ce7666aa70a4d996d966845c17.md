# Prompt-driven CV tailoring — remove Fact Guard, feed the JD to the draft LLM

## Goal
Generation becomes: plan → draft (LLM rewords content toward the job description) → page-budget fit → PDF extraction gate → persist. No claim blockers, no claim confirmations, no "resolve blockers to download". Facts stay fixed (rewording only); technical checks (page budget fit loop in `fit.ts`, extraction gate in `verify.ts`) are kept untouched.

## Part 1 — Make the draft prompts actually see the job description
Today `draftCV`/`draftLetter` only get a digest (keyword list + top-5 requirement phrases); the full `JobAnalysis.jdText` never reaches the prompt.

1. `src/lib/generation/plan.ts` — preconditions stage already loads the analysis; add `jdText` to the plan output (`CVPlan`/`LetterPlan`), capped at ~12,000 chars (JD max is 100k — cap keeps premium-tier calls sane).
2. `src/lib/generation/draft.ts` — `buildTaskPayload`/`buildLetterTaskPayload` pass `jobDescription: plan.jdText`.
3. `src/lib/llm/tasks/generatetailoredcv.ts` + `generatecoverletter.ts` — add `jobDescription` to the input schemas; render it in the user prompt; strengthen the system prompt: "reword summary/bullets to mirror the job description's terminology, priorities, and phrasing — while keeping every employer, date, number, and skill exactly as in the source; zero invention."

## Part 2 — Remove Fact Guard
- **Delete files**: `src/lib/generation/factguard.ts`, `src/lib/llm/tasks/factguard.ts`, `src/components/generation/ClaimReview.tsx`.
- **Pipeline** (`src/lib/generation/pipeline.ts`): drop the `factguard` stage and `StageName`; draft warnings (`VERBATIM_FALLBACK`, `UNCERTAIN_TRANSLATION`) go into a warnings-only validation report (no blockers are ever produced); gate/persist stages no longer depend on a blockers-bearing report.
- **Download gating** (`src/lib/generation/repository.ts` `computeDownloadable`): becomes artifacts-present + `extractionCheck.passed` for pdf — the validation report no longer gates anything. Remove `recordConfirmation`/`findConfirmedFingerprints`/`parseFingerprints` and the claim-edit helpers (`updateVersionContent`, `setVersionValidationReport`); keep the `validationReport` DB column (still written, warnings-only, shown passively).
- **Prisma**: one migration dropping `GeneratedDocument.confirmations` (fingerprint store, now unused). `validationReport`/`revision` columns stay to avoid destructive churn.
- **API**: delete the claim routes (`.../document/claims` PATCH/DELETE, `.../claims/[claimId]/confirm`); download route loses `FACTGUARD_UNAVAILABLE`/`BLOCKERS_UNRESOLVED` (keep the `EXPORT_GATE_FAILED` path); remove both codes from `src/lib/api/errors.ts`; document poll route keeps returning the (now warnings-only) report.
- **UI** (`GenerationPanel.tsx`): remove blocker banners, "resolve N blockers first" gating, and `<ClaimReview>`; keep a small passive warnings display. Update `client-messages.ts` flag explanations to warning codes only.

## Part 3 — Benchmark (slice 009) rework
Fact Guard is load-bearing in the benchmark, so this is required to keep it compiling: remove `factGuard` from `LLM_TASK_IDS` and the models config, drop `computeGroundedClaimRate`, `fail_closed_verified`, and the semantic/deterministic `caughtBy` variant grading from `runner.ts`/`variants.ts`/`metrics.ts`/`report.ts`. Keep the remaining benchmark machinery (latency/cost/extraction metrics). Variant fixtures with semantic-class expectations get pruned.
