# Code Review — ProfileForge

**Date:** 2026-11-08 · **Branch:** main @ `8f7730f` · **Working tree:** clean

**Method:** four independent read-only review passes (security/authz; generation & matching domain
logic; data layer & infrastructure; frontend React) covering the full `src/` tree — 146 source
files, 32 API routes, 18 Prisma models, 12 migrations, CI, configs, client code — plus a structural
pass. Nothing was modified; no builds or tests were run. Next.js 16 framework claims were verified
against the bundled docs in `node_modules/next/dist/docs/` (`proxy.ts` naming, `bodySizeLimit`
scope, `poweredByHeader` default).

## 1. Architecture summary

**Stack:** Next.js 16.4.2 App Router + React 19 + TypeScript, Prisma 7 + Postgres
(`@prisma/adapter-pg`, docker-compose on :5435), zod 4, `@node-rs/argon2`, docx/mammoth/pdf-lib/unpdf,
franc; Vitest (440 tests) + Playwright e2e + a transcript-replay benchmark; GitHub Actions CI (green).

**Shape:** single-process App-Server app, server-rendered pages + thin client views, all data access
through `src/lib/*` repositories owned by per-user scoping (feature 008). No separate worker:
generation jobs run in-process (`runGenerationJob`, `src/lib/generation/pipeline.ts:291`), deduped by
a `globalThis` in-flight map.

**Data flow:** upload (`/api/cv/upload`, content-addressed sha256 storage) → text extraction
persisted on `SourceDocument` → LLM parse via user's own OpenRouter key (AES-256-GCM-encrypted at
rest, `src/lib/settings/crypto.ts`) → ≥95% word-containment verification of parsed bullets
(`src/lib/validation/sourceContainment.ts`) → import into a versioned `Profile` (every mutation
bumps version + writes a `ProfileSnapshot` in one transaction, `src/lib/profile/repository.ts:139-153`)
→ JD paste → requirements → deterministic match (exact → alias → evidence-validated semantic,
`src/lib/matching/`) → generation job (`queued→running→succeeded/failed`; plan → id-keyed LLM draft →
page-budget fit loop → pdf-lib/docx render → two-level extraction gate) → download gated on
`extractionCheck.passed` with a path-traversal guard.

**Route map (32):** `auth/` (login, logout, register, session) · `cv/` (upload, `[id]`
GET/PATCH/DELETE, `[id]/parse`) · `jobs/` (CRUD + extract/confirm/match/requirements/rerun) ·
`generations/` (create/list, get, cancel, retry, document, download, omission restore) · `profile/`
(get/patch, entries POST + `[section]/[id]` PATCH/DELETE, import, versions, restore) · `settings/`
(get/put, models, validate-key) · `validation/claims`. Every route calls `requireUser()`; pages gate
server-side before client mount.

**Largest files:** `src/lib/generation/plan.ts` (1152), `GenerationPanel.tsx` (641),
`profile-view.tsx` (618), `lib/profile/repository.ts` (535) — these four concentrate the complexity
and most findings.

## 2. Highest-risk areas (ranked)

1. **Draft-stage grounding is prompt-only.** The core product promise ("nothing is ever invented")
   is enforced by prompt text after Fact Guard removal; provenance is attached to LLM output
   unconditionally and the export gate checks render fidelity, not truth —
   `src/lib/generation/draft.ts:45-125`, `pipeline.ts:110-113`, `verify.ts:14-19`.
2. **Generation job lifecycle + spend accounting.** Non-atomic status transitions, retry-vs-sweep
   race, no kickoff dedupe, and a cost cap that's blind to failed/repair calls — all around
   spend-bearing LLM work: `src/lib/generation/repository.ts:54-165`, `pipeline.ts:291-363`,
   `src/lib/llm/usage.ts:21-36`, `transport.ts:78-129`.
3. **One IDOR: profile entry DELETE has no ownership check** —
   `src/lib/profile/repository.ts:229-235` (every other mutation funnels through
   `findEntry(..., profile.id)`).
4. **Profile-editor autosave/restore lifecycle** (`src/app/profile/profile-view.tsx`) — restore can
   be silently reverted by pending autosave timers; overlapping basics flushes revert each other.
5. **Resource limits & abuse:** upload buffers the entire body before size check; no cap on
   extracted-text expansion; no rate limiting anywhere; cost cap is per-run, not per-user.
6. **Retired default model** (`minimax/minimax-m3.1-flash:free`) ships as the default for every new
   user — breaks first-run extraction (`prisma/schema.prisma:280`, `src/lib/settings/store.ts:10`).

## 3. Prioritized findings & recommended fixes

### P0 — fix now

1. **[HIGH] IDOR on entry DELETE** — `src/lib/profile/repository.ts:229-235`: deletes by bare `id`;
   any authenticated user can delete another user's experience/education/skill/… row (cascade takes
   its bullets). Secondary: a missing id surfaces as P2025 → 500 instead of 404. **Fix:**
   `await findEntry(tx, section, id, profile.id)` before `delete(...)` (same pattern as
   `updateEntry` at :200-212); map P2025 → `NOT_FOUND`.
2. **[HIGH] Retired economy model is the shipped default** — `prisma/schema.prisma:280`,
   `src/lib/settings/store.ts:10`; CI itself documents the 2026-10-22 retirement
   (`.github/workflows/ci.yml:57-59`). Every new user's first extraction fails with 404 until they
   change Settings. **Fix:** change the default in schema + `DEFAULT_SETTINGS` (one `SET DEFAULT`
   migration); decide explicitly whether stored rows get a data migration (STATUS.md already tracks
   this item).
3. **[HIGH] No mechanical grounding check on rewritten claims** — `src/lib/generation/draft.ts:82-94,113`:
   `sourceBulletIds`/`summaryProvenance` attached regardless of what the model wrote; the ≥95%
   containment check runs only at ingestion and export gate, never against the tailored rewrite,
   while the raw 12k-char JD is in the rewrite prompt (`plan.ts:1022,1085`). **Fix:** cheap
   deterministic post-merge check in `mergeKeyedDraft`/`mergeKeyedLetterDraft` — every number, date,
   duration and capitalized proper noun in the output must appear in the union of its `sourceText` +
   snapshot meta under `normalizeForContainment`; emit a `ValidationFlag` or clamp to verbatim
   fallback on violation.

### P1 — fix soon

4. **Generation job lifecycle races** (spend + wrong terminal states):
   - Transitions are read-then-write, not atomic — `repository.ts:67-93,144-149` +
     `pipeline.ts:291-301`; only single-process safe. **Fix:** guarded
     `updateMany({ where: { id, status } })`, abort on `count === 0`; scope
     `markFailed`/`markSucceeded` to the runId.
   - `retryJob` (:109-124) returns a job to `queued` without touching `createdAt`; the 60s stale
     sweep (:153-164) then kills fresh retries racing a 1.5s poller. **Fix:** sweep on `updatedAt`,
     or write `queuedAt`.
   - No dedupe on `(analysisId, kind)` — `src/app/api/generations/route.ts:20-22` +
     `repository.ts:17-46`: double-submit runs two full pipelines; the loser ends as a spurious
     failed job via P2002. **Fix:** 409 on existing queued/running job; optionally a partial unique
     index (`WHERE status IN ('queued','running')`).
   - `inFlight` swallow window after `markCancelled` — `pipeline.ts:350-363`: a retry can return
     early and sit `queued` until the sweep marks it INTERRUPTED.
5. **Cost-cap blind spots** — `src/lib/llm/usage.ts:21-36`, `transport.ts:78-129`: repair-loop
   attempts overwrite `lastUsage` and only the success branch records; `usage.cost ?? 0` logs zero;
   `recordUsage` swallows insert errors; check-then-log overshoots under parallel calls. **Fix:**
   record usage on every attempt (including failed ones, tagged); warn loudly on missing cost;
   document or serialize the per-run concurrency.
6. **Upload memory DoS** — `src/app/api/cv/upload/route.ts:17-27`: `formData()` buffers the whole
   body before `MAX_UPLOAD_BYTES` is checked (`storage.ts:30-32`); route handlers have no built-in
   cap (verified in bundled docs). **Fix:** reject on `Content-Length` > ~10.5 MB with 413 before
   parsing; optionally enforce at proxy level.
7. **Profile editor restore/autosave lifecycle** — `src/app/profile/profile-view.tsx`:
   - Restore doesn't clear `pendingBasics.current` (:142) or entry timers, and Basics use
     `defaultValue` (:408,417) so restored basics never display — pending autosave then PATCHes
     pre-restore values back over the restore (:212-227; server replaces whole basics,
     `repository.ts:160-166`). **Fix:** cancel all pending timers + clear `pendingBasics` at the top
     of `restore()`; remount Basics via `key={profile.version}`.
   - Overlapping basics flushes can revert each other's field edits (full-object PATCH, stale
     `lastBasicsSent`). **Fix:** merge-patch semantics server-side and send only pending keys, or
     serialize flushes.
   - No flush on unload → last 800 ms of edits silently lost on tab close (:136,165-174). **Fix:**
     flush with `fetch({ keepalive: true })` on `visibilitychange`/unmount.
8. **Requirements refetch clobbers typing** — `src/app/jobs/[id]/job-detail-view.tsx:82-85,106,242`:
   controlled inputs + unconditional `load()` after every save; typing during the PUT visibly
   reverts. **Fix:** uncontrolled rows or `syncedText`-style merge (as `BulletEditor.tsx:21` does).
9. **One failed poll freezes generation UI forever** —
   `src/components/generation/GenerationPanel.tsx:193-196,230-236`: `refresh()` ignores failures,
   the effect re-arms only on `poll` change → stuck "running", controls disabled, no error. **Fix:**
   handle failure with capped retries + error state; treat 404 as terminal.

### P2 — should fix

10. **No cap on extracted-text expansion** — `upload/route.ts:43-77`, `lib/parsing/docx.ts:6-11`:
    10 MB gates compressed bytes only; mammoth/unpdf output is unbounded before storage. XXE ruled
    out; billion-laughs unverified. **Fix:** cap extracted text length and decompression ratio.
11. **No rate limiting; cap is per-run not per-user** — `usage.ts:21-36`: every entry mints a fresh
    `runId`; login/parse/generation can be hammered (argon2 = CPU amplifier; env-key override + one
    compromised account = shared-key drain). **Fix:** limiter on `/api/auth/*`, rolling per-user
    spend cap alongside the per-run cap.
12. **Restore-vs-deleted-document FK violation** — `repository.ts:502-506`: old snapshots keep
    `sourceDocumentId` of documents deleted since; restore 500s. **Fix:** validate snapshot ids
    inside the transaction; null them + flip provenance to `user_entered` when gone.
13. **Unguarded last-write-wins autosave** — `repository.ts:160-172,192-227`: `profile.version` is
    maintained but never used as a concurrency token; two tabs silently overwrite. **Fix:** accept
    expected `version`, `updateMany({ where: { id, version } })`, 409 on miss.
14. **Substring skill-usage check** — `src/lib/matching/engine.ts:201-204`: bare `includes()`
    decides `strong` vs `partial` — "java" matches "javascript", "c" matches nearly anything,
    corrupting the 60/30/10 score. **Fix:** reuse the word-bounded predicate from
    `longestContainedTerm` (:190-195).
15. **Phantom blank page inflates `pageCount`** — `render/template.ts:313-319`, `designed.ts:184-191`:
    page appended on the post-last-line `advance(spaceAfter)` → fit loop demotes a real, needed unit
    as `page_budget`. **Fix:** defer page creation until the next actual draw.
16. **Restored omissions use positional ids across versions** — `plan.ts:548-557,747-751`:
    rank-positional claim ids protected in a *new* ranking can protect the wrong bullet. **Fix:**
    key omissions by stable `sourceIds`.
17. **v1-pinned snapshot unresolvable** — `plan.ts:1036-1044` + `repository.ts:139-153`:
    `commitMutation` only snapshots the *new* version; old v1-pinned retries fail in preconditions.
    **Fix:** snapshot pre-mutation state under the old version too.
18. **Docker binds Postgres on 0.0.0.0 with known creds** — `docker-compose.yml:13,34`. **Fix:**
    `127.0.0.1:5435:5432` / `127.0.0.1:5434:5432`.
19. **Failed re-upload wipes open draft; double-upload** — `upload-view.tsx:84-86,178`:
    `parsed`/`imported` cleared before the request; button not disabled in flight. **Fix:**
    `uploading` state; clear only on success.
20. **Load paths ignore `res.ok`** — `profile-view.tsx:145-157`, `job-detail-view.tsx:79-91`,
    `settings-view.tsx:31-38`, `jobs-view.tsx:41-44`: expired session/deleted row → eternal
    "Loading…". **Fix:** check `res.ok`, redirect 401 → `/login`.
21. **Re-run button not disabled in flight** — `job-detail-view.tsx:302-306` → duplicate analyses,
    double cost.
22. **Structured-output probe fails open** — `settings/models.ts:47` returns `true` when model
    listing is unavailable → OpenRouter rejects `require_parameters`. **Fix:** fail closed (`false`);
    prompt-only JSON still validates locally.
23. **`secure` cookie depends on `x-forwarded-proto`** — `auth/session.ts:13-26`. **Fix:** default
    `secure: NODE_ENV === "production"`.
24. **Unbounded credential/key lengths** — `auth/schemas.ts:6-9` (no password max → argon2
    amplification), `settings/route.ts:35-40` (no key max). **Fix:** `.max(128)` / `.max(254)` /
    `.max(300)`.
25. **Semantic-match errors collapse cause** — `jobs/[id]/match/route.ts:78-82`:
    `LLM_KEY_INVALID`/`COST_CAP_REACHED` become opaque `semantic-matching-unavailable`.
26. **Money in Float** — `schema.prisma:282,296`; two inconsistent rounding sites
    (`usage.ts:23-28` vs `repository.ts:359`). **Fix:** `Decimal(12,6)` or one shared rounding.
27. **`next.config.ts` hardening** — `poweredByHeader` on by default, no security headers,
    machine-specific `allowedDevOrigins` IP (`next.config.ts:3-19`).
28. **Real PII committed** — `scripts/seed-gui-test.ts:27-42` (name, emails, phone, LinkedIn).
    **Fix:** synthetic data; scrub if repo goes public.
29. **Empty cover letter can succeed** — `draft.ts:257-259`: zero-paragraph letter passes the gate.
    **Fix:** fail when merged letter has no paragraphs.
30. **CI double-runs every PR commit** — `ci.yml:17-19` (unfiltered `push` + `pull_request`,
    non-cancelling groups). **Fix:** `push: { branches: [main] }`.
31. **`db.ts` gaps** — `src/lib/db.ts:4-15`: no `DATABASE_URL` validation, no explicit pool config,
    no `$disconnect` on shutdown.

### P3 — hygiene

actually implements keep-or-rename — merge exists only in the import flow (`repository.ts:425-436`).

## 4. Verified-OK (load-bearing things that are right)

Session tokens are 32 random bytes stored SHA-256-only with httpOnly/sameSite=lax cookies and
dummy-hash timing equalizer (`auth/session.ts:29-39`, `login/route.ts:9-25`); argon2id at
OWASP-aligned params; per-user keys AES-256-GCM with scrypt-derived key, only masked hints leave the
server, `redact()` before any log line; CSRF covered by SameSite=Lax + JSON-only mutations; all
other routes scope by owner (`findFirst({ id, userId })` / `analysis: { userId }`); download
path-traversal guarded; no `dangerouslySetInnerHTML`/SSRF anywhere; all 12 migrations match schema
statement-for-statement; test DB resets triple-guarded against hitting a real DB; fit loops provably
terminate; selection sorts stable with snapshot-order tie-breaks; error classification by HTTP
status, not body strings; benchmark replay fails loud (`TRANSCRIPT_MISS`), not silently.

## 5. Bottom line

The codebase is in strong shape — isolation, secrets, migrations, and test infrastructure are
notably solid, and most of the surface checks out under adversarial reading. Land first: the
**entry-DELETE ownership fix** (one line, closes the only IDOR), the **retired default model**
(breaks first-run for every new account, already tracked in STATUS.md), and a **deterministic
grounding check on the rewrite stage** (the one place where the product's central promise rests on
prompt text alone). After that, the job-lifecycle/cost-cap cluster and the profile-editor restore
races are where real money and silent data loss live.
